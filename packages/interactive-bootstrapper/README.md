# Interactive Bootstrapper

Starts and manages local development services. A port of Lattice's `interactive-bootstrapper`: it picks services
from [`@example/sears-catalog`](../sears-catalog), runs prerequisites, and runs the services with
[overmind](https://github.com/DarthSim/overmind) from a generated Procfile.

Requires `brew install overmind tmux`.

## Startup modes (`pnpm start`)

When you run `pnpm start` with no flags, you're first shown a top-level menu asking how you want to start. Use
the arrow keys to move and `enter` to choose:

| Mode       | What you get                          | Services |
| ---------- | ------------------------------------- | -------- |
| `Minimum`  | Required services only (fastest)      | 2        |
| `Balanced` | Minimum + common services             | 3        |
| `Full`     | Every service in the catalog          | all      |
| `Custom`   | Drop into the detailed service / preset picker | you pick |

Every mode except `Custom` then asks for launch options and boots. `Custom` falls through to the checkbox
picker, where you can hand-select individual services and presets.

Each mode maps to a preset in [`sears-catalog`](../sears-catalog/src/presets/index.ts) (`minimumPreset`,
`balancedPreset`, `fullPreset`); treat it as the source of truth.

### Launch options

| Option | Does |
| --- | --- |
| Install new node_modules | `pnpm install` |
| Generate code | `turbo run codegen` for the selected apps and the packages they depend on (e.g. proto packages) |
| Fast restarts | Keeps a warm standby process per Nest app, so a restart after an edit skips loading dependencies (on by default; costs an idle process per app) |
| Enable Debugging | Asks which service to debug, opens its inspector on a static port, and writes `.vscode/launch.json` |

Your mode, picks and launch options are cached in `~/.cache/example-monorepo`, shared across checkouts.

### Skipping the menu

```bash
pnpm start --mode balanced           # pick a mode directly
pnpm start --preset Goals --auto-run # run a named preset with no prompts
pnpm start --auto-run                # reuse whatever you picked last time
pnpm start --manual-run              # required services only, no prompts (CI does this)
```

`--preset` alone skips the mode menu but still opens the picker with the preset selected; add `--auto-run` to skip
it. Run `pnpm start dev --help` for the full flag reference and precedence order.

Tools can reuse the service picker without launching services:
`pnpm start --selection-fd 3 3>selection.json` writes the selected service names as a JSON array, keeping
terminal prompts separate.

## Working with overmind

Once `pnpm start` is running, every service is an overmind process in tmux:

```bash
overmind connect api-rspack       # just api-rspack's logs and terminal; detach with ctrl-b d
overmind restart api-rspack       # restart one service
overmind stop api-rspack          # stop one service
overmind restart           # restart everything
```

`.overmind.env` (written from `src/overmindDefault.example.env` the first time) holds your overmind settings. It's
git-ignored, so change it freely.

## The Procfile

`src/Procfile` is generated by `pnpm codegen` (`src/genProcfile.ts`) from the catalog. Don't edit it by hand. For
each service it:

- `cd`s into the package and runs its script, following `pnpm <script>` chains to the real command and pointing
  CLI tools at the package's `node_modules/.bin`;
- exports the catalog's `env` (`PORT`, `GRPC_PORT`, `SERVER_TYPE`, `SERVER_MODE`), so every port is set in one
  place;
- exports `LABUILD_COORDINATOR_PROC_NAME` and a static `LABUILD_DEBUG_PORT`, kept stable in `src/debugPorts.json`.

Generation fails on a port collision. `pnpm -F @example/interactive-bootstrapper suggest-unused-port` prints the
first free port.

## Node.js debugging

Check "Enable Debugging", pick a service, then attach with the generated `Debug <service>` configuration in VS
Code. Only the chosen service opens an inspector, on its port from `src/debugPorts.json`. You can also set
`DEBUG_SERVICE=<service>` with `ENABLE_NODE_DEBUGGING=true` yourself. Nest apps get this from
[`@example/rspack-configs`](../rspack-configs).

## Adding a service

`pnpm gen service` and `pnpm gen subgraph` add their processes to the catalog and regenerate the Procfile. For
anything else, add an entry to [`deploymentCatalog.ts`](../sears-catalog/src/deploymentCatalog.ts) and run
`pnpm codegen`.
